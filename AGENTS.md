## 1. Obiettivo del progetto (il perché)
QqQ lab è un programma DIDATTICO per il laboratorio di inquinanti del corso (UniTO, titolare del progetto: Federico Cristaudo, dottorando). Gli studenti lavorano con dati LC-MS di un triplo quadrupolo SCIEX 3200 QTRAP (risoluzione unitaria, ESI positivo, Analyst 1.6.3) per studiare i prodotti di trasformazione (TP) di un inquinante degradato in fotocatalisi (TiO2, esperienza 3 del corso, tempi 0-60 min).

Principi che NON vanno violati:
1. **Pedagogico: il programma NON dà le risposte.** Non propone automaticamente "ecco i TP". Lo studente parte dal full scan, sceglie lui quali m/z estrarre (XIC), sovrappone cromatogrammi, rinomina tracce, integra i picchi, annota, disegna molecole, frammenti e vie di trasformazione. Il programma è uno strumento di esplorazione, non un oracolo. Strumenti esterni (es. BioTransformer) sono opzionali e separati. Le schede Attribuzioni e Suggerimenti sono state tolte (2026-10-05, decisione di Federico): non reintrodurle.
2. **Leggero, offline, modificabile dagli studenti.** Solo Python >= 3.11 + numpy, interfaccia web locale in HTML/JS semplice senza build, nessun servizio in rete. Codice leggibile e commentato. Non aggiungere dipendenze pesanti.
3. **Interfaccia e testi per l'utente in italiano.** Codice e commenti in inglese.
4. **Onestà scientifica.** Risoluzione unitaria: un m/z è un candidato, non un'identificazione. Mostrarlo sempre così.

Flusso dello studente (esperienza 3): G1 fotocatalisi + standard dell'inquinante incognito, ricerca transizioni; G2 retta di taratura MRM, quantificazione, scan dei campioni per gli intermedi; G3 Product Ion Scan (MS2) sui tempi con più intermedi. Relazione finale: tabella m/z intermedi con ioni prodotto + grafici di scomparsa dell'inquinante ed evoluzione degli intermedi vs tempo (la tabella integrazioni con cinetica serve a questo).

Dettagli dell'esperienza: TiO2 400 mg/L; cuvetta 2.5 mL inquinante + 2.5 mL TiO2; t = 0, 5, 10, 15, 30, 45, 60 min; filtrazione 0.45 um; C18, inquinante 15 mg/L, HCOOH 0.05% / ACN gradiente, QqQ ESI+.

## 3. Mappa del codice
Radice: `QqQ_lab/tpfinder/` (il pacchetto Python è la sottocartella `tpfinder/`; nella radice non ci sono moduli Python).
- `tpfinder/cli.py`: comandi (`app`, `draft`, `convert`, `candidates`, `metodo`; `demo` e `serve` tolti con la scheda Suggerimenti). Entry: `python -m tpfinder app` (cartella di lavoro predefinita `~/TPFinder_lavoro/sessione_...`).
- `tpfinder/server.py`: server HTTP locale (solo 127.0.0.1), classe `App` + handler. GET: `/api/session`, `/api/chrom`, `/api/xic`, `/api/mrm`, `/api/method`, `/api/map` (mappa RT x m/z, float32 base64), `/api/spectrum` (anche `bgk`, `bgrt0`, `bgrt1` per lo spettro di fondo), `/api/formula?f=...&adduct=[M+H]+` (formula errata = HTTP 400), `/api/notebook`, `/export/*`; POST: `/api/upload`, `/api/explore`, `/api/notebook`, `/api/new`, `/api/remove`, `/api/build`. Errori sempre come JSON `{"error": ...}`. In modalità esplora `/export/session.json` e gli endpoint dei candidati rispondono 400 con testo italiano.
- `tpfinder/explore.py`: sessione di esplorazione (`Session`, `Item`). `Item.kind()` = `full` | `ms2` | `mrm`, `total()` (TIC/BPC), `xic()`, `spectrum(..., bg={item, rt0, rt1, factor})` (sottrazione di fondo bin per bin con taglio a zero, via `_binned`), `mrm()`, `method()`, `ionmap()`; `Session.grid()` (griglia comune per la mappa). File MRM: RT e polarità dai cromatogrammi SRM (`_srm_rt_range`, `_header_polarity`).
- `tpfinder/reader/mzml.py`: lettore mzML con mmap (nessuna libreria esterna): scan, array base64/zlib, cromatogrammi SRM, metadati.
- `tpfinder/reader/ole.py` + `methodinfo.py`: decodifica dei parametri del metodo da .dam/.wiff (CUR, GS1, GS2, IS, DP, EP, CE). Serve SOLO al docente (`python -m tpfinder metodo FILE -o out.json`); il risultato è `tpfinder/config/metodo_laboratorio.json`, letto dal popup "Metodo". Gli studenti non hanno i wiff: non farne dipendere l'app.
- `tpfinder/core/`: `analysis.py`, `score.py`, `peaks.py` (candidati TP, punteggi, picchi: vecchio flusso, oggi senza interfaccia; restano per il comando `candidates` e per i test).
- `tpfinder/console.py`: uscita del Terminale (intestazione, spunte, spinner, colori solo su terminale vero, ASCII dove servono); solo libreria standard e Python >= 3.8 perché lo usa anche `scripts/avvia.py`. `serve()` non ristampa l'intestazione se c'è `QQQ_HEADER=1` (lo imposta l'avviatore).
- `tpfinder/chem/elements.py`: masse monoisotopiche, `parse_formula` (accetta parentesi), `formula_mz(formula, adduct)` (massa neutra, m/z esatto, `mz1` a 1 decimale, `nominal`; arrotondamento half-up `round_half_up`, non "del banchiere"), addotti (`ADDUCT_SHIFT`). `chem/transformations.py`: candidati dalle reazioni di `config/trasformazioni.csv`.
- `tpfinder/project.py`: file `esperimento.toml`, `guess_sample()` indovina tipo e tempo dal nome file (`t15`, `blank`...).
- `tpfinder/convert.py`: wiff -> mzML con msconvert (non testato: non c'è msconvert sul Mac di sviluppo).
- `tpfinder/demo.py`: dati sintetici per demo e test.
- `tpfinder/config/`: `testi.toml` (messaggi), `soglie.toml`, `trasformazioni.csv`, `metodo_laboratorio.json`.
- `tpfinder/web/`: front end statico.
  - `index.html`: struttura, CSS, schede Dati e Disegno, caricamento file (con istruzioni MSConvert per i .wiff in `#wiffhelp`), popup Calcolatrice m/z (`#np-calc`), pulsanti in alto a destra Tavola periodica (`#np-pt`), Addotti (`#np-ad`), PubChem (`#np-pc`, solo link esterno) e BioTransformer; lo script inline contiene solo gli helper comuni (`setup`, `nice`, `fmt`, `css`, `M` = margini dei grafici), le viste e la pagina iniziale; logo e favicon (`logo.png`, `favicon*.png/ico`, `apple-touch-icon.png`, `app-icon-256/512.png`; concept originale in `docs/logo_concept.jpg`, raster ~450 px).
  - `explore.js`: scheda Dati. Esportazioni per Excel in italiano (`csvOf`, `plotCsv`, `cell`): punto e virgola fra le colonne, virgola decimale, UTF-8 con BOM, intestazioni in italiano; pulsante CSV in ogni pannello (tracce visibili affiancate) e tabella Integrazioni. Le tabelle e i grafici della relazione (taratura, cinetica) li costruiscono gli studenti in Excel: non aggiungere calcoli che li facciano al posto loro. Profilo isotopico teorico sopra lo spettro (clic destro → "Confronta con il profilo isotopico", `p.iso`, cerchi rossi allineati al centroide del picco osservato più vicino, zoom automatico sul profilo). Il taccuino si salva solo se è cambiato (`nbLast`). Vista iniziale (`defaultLayout`): TIC di tutti i file in alto a tutta larghezza, spettro sotto al RT di intensità massima (`apexSpectrum`), MRM sotto; i file MRM non entrano nel TIC se ci sono file a scansione. Pannelli a tutta larghezza (`p.full`, `fitWidth`; nuovi pannelli in coda con `place`; "Ordina" = uno sotto l'altro); elenco file richiudibile (`setFold`, `#ffold`/`#funfold`, salvato in `NB.ui.fold`); assi con titoli e senza griglia orizzontale (`axes` + `frame`); PNG dei grafici su sfondo bianco (`whiteCanvas`); il ResizeObserver osserva anche il canvas. Pannelli cromatogramma/spettro/XIC/MRM/mappa RT-m/z; cursore con valori e linea sincronizzata; etichette RT dei picchi (`pickPeaks`, spente di default); vista impilata e scala log; Ctrl/Cmd+rotella = zoom, Maiusc+trascina = sposta, doppio clic = vista intera, clic sulla legenda = nascondi traccia; integrazione; sottrazione del bianco e baseline SNIP su chrom/xic/mrm (`corrected`, `snipBaseline`; opzioni `p.bk`, `p.snip`, `p.snipw`; spettri `p.bg`, `p.bw0`, `p.bw1`); m/z inseriti arrotondati a 1 decimale (`addTrace`), campo "m/z o formula" (`addFromText`); popup Metodo/BioTransformer; esportazioni; salvataggio sessione (`uiSave`, anche su `pagehide` con fetch keepalive).
  - `teoria/`: scheda **Teoria**, modulo statico separato (HTML/CSS/JS senza dipendenze, funziona anche da `file://`): `index.html` + capitoli `01-tp` ... `11-glossario` (`08-frammentazione` = chimica della CID); guida per modificarla a mano: `teoria/LEGGIMI.md`, `teoria.css`, `teoria.js` (capitoli in `CHAPTERS`, menu laterale, indice della pagina, avanti/indietro, aiuti per i grafici `TP.*`), simulazioni `sim-quad.js` (Mathieu/Floquet: diagramma di stabilità, traiettorie, scansione), `sim-esi.js` (Rayleigh, fissioni, competizione per la carica), `sim-qqq.js` (modalità di scansione, CE/Ecm, dwell), `sim-misc.js` (cinetica A→B→C, isotopi, libero cammino medio, differenze di massa), `sim-frag.js` (competizione RRK riarrangiamento/scissione, calcolatrice delle perdite neutre). In `index.html` è un iframe `#tframe` caricato alla prima apertura (`/static/teoria/index.html`); `Teoria QqQ lab.html` nella radice la apre da disco. Regola: esempi solo su composti che NON sono tra gli inquinanti dei metodi del laboratorio (l'esempio svolto è l'atrazina), niente risposte sul composto dell'esperienza.
  - `draw.js`: scheda Disegno con Ketcher. Scritte automatiche (`#lb-on`): sotto ogni struttura formula bruta + massa monoisotopica intera (M, oppure m/z se c'è una carica: `structures`, `labelParts`), sopra ogni freccia la differenza fra le strutture prima e dopo (es. "+O Δm +16": `arrowDeltas`). Sono disegnate in un gruppo `#qqq-labels` dentro l'SVG di Ketcher (coordinate = `atom.pp` x `microModeScale`), quindi NON fanno parte della struttura (undo, .ket, SMILES intatti); nelle immagini esportate diventano testo Ketcher (`ketWithLabels`, pedici Unicode). Riquadro "Selezione (frammento)" (`showSelection`, evento Ketcher `selectionChange`): formula degli atomi selezionati con gli H che hanno nella molecola, legami tagliati, ipotesi di ione (pezzo chiuso con H e protonato, carica sul taglio, ESI−) con pulsante XIC. La gomma su un legame = due frammenti con due scritte. Lo switch della modalità macromolecole di Ketcher è nascosto con CSS (`hideMacro`). Formula/massa/addotti delle strutture; card "Didascalia per la relazione" (spenta di default) (`addCaption`, testo copiabile e scritta sotto la struttura in PNG/JPEG/SVG, salvata in `NB.cap`).
  - `help.js`: aiuto contestuale. Ogni `<button class="hq" data-help="chiave">?</button>` apre un riquadro con il testo `HELP[chiave]` (titolo + spiegazione, in italiano); nei pannelli il "?" lo aggiunge `addPanel` con `helpBtn("pnl-" + tipo)`. Per una funzione nuova: aggiungere la chiave in `HELP` e il pulsante dove serve.
  - `tables.js` + `elements.js`: finestra "Tavola periodica / Addotti / Isotopi / Perdite neutre". Tavola: passando sopra un elemento peso atomico medio, massa monoisotopica, isotopi con massa esatta, abbondanza e differenza dal principale; clic = fissa; righe ad altezza fissa (lo stile lo inietta `tables.js`), il riquadro informazioni scorre. Addotti ESI+/ESI− con m/z da massa o formula e Δ da [M+H]+/[M−H]−. Isotopi: profilo isotopico calcolato qui (`isoPattern`: convoluzione per elemento, raggruppata per massa intera come a risoluzione unitaria; `ionCounts` aggiunge l'addotto), nessuna libreria esterna. Perdite neutre: solo massa intera. `window.QQQRef` espone `isoPattern`, `ionCounts`, `ADD`, `massOf`. `elements.js` è generato da `tools/genera_elementi.py` (masse isotopiche da OpenChemLib, pesi atomici da Ketcher, abbondanze IUPAC scritte nello script solo per gli elementi tipici in LC-MS): non modificarlo a mano.

Ketcher offline ha già: Valori calcolati (Alt+C, anche sulla selezione), controllo struttura (Alt+S), H espliciti, visore 3D, libreria (Shift+T), esportazione CDXML/MOL/SDF/InChI, stile ACS nelle impostazioni.

## 5. Come lavorare ed eseguire i test
- Python >= 3.11 richiesto (`tomllib`); l'ambiente del Mac usa il più recente installato (vedi `scripts/avvia.py`; a ottobre 2026: 3.14.x stabile, 3.15.0 previsto il 9/10). La shell vista da device_bash è una VM Linux con Python 3.10 e senza Chromium (il `.venv-tpfinder` del Mac punta a un Python macOS e lì non funziona). Quindi: staging dei file con device_stage_files nel container cloud (Python 3.13, numpy, Playwright, Chromium), `pip install --break-system-packages pytest`, test lì, e i file modificati tornano sul Mac con device_commit_files. Escludi dallo staging venv, cache e `.DS_Store`.
- Test unitari: `python3 -m pytest -q tests`. Se nel container PyPI è bloccato (pip dà "No matching distribution"), basta un piccolo sostituto di pytest (`approx`, `raises`, `fixture`, `tmp_path`, `tmp_path_factory`) che esegue le funzioni `test_*` di `tests/test_pipeline.py`.
- Prima dell'e2e controlla la sintassi JS: `node --check` su `explore.js`/`draw.js` e sullo script inline di `index.html` (estratto in un file). Attenzione: gli script classici condividono i `const` globali, non ridichiarare nell'inline ciò che è già in `explore.js`.
- App: `python -m tpfinder app --workdir /tmp/wd1 --port 8811 --no-open`, poi apri `http://127.0.0.1:8811/`.
- E2E: dalla radice `tpfinder/`, `python3 tests_e2e/e2e3.py` (poi `e2e4.py`, `e2e5.py`, `e2e6.py`, `e2e7.py`). I percorsi sono relativi: codice = cartella padre di `tests_e2e`, mzML = `../esempio_conversione/mzml` (oppure variabile d'ambiente `QQQ_MZML`), screenshot in `tests_e2e/shots/`. Caricano 5 mzML (B_FullMass-t0/t15/t60, B_MS2-t15, B_MRM-t0) con `set_input_files("#pick", ...)`, clic "Apri i dati". Controlla SEMPRE gli errori JS/HTTP stampati a fine esecuzione e guarda gli screenshot.
- Un front end non provato nel browser è considerato rotto: non dichiarare "funziona" senza e2e.
